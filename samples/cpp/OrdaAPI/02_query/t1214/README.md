# 예상체결가상/하한가조회 (t1214)

Visual Studio 2010에서 OrdaAPI-t1214-ExpectedPriceLimits.sln을 열고 Win32 Debug 또는 Release로 빌드합니다. 실행 작업 디렉터리는 저장소의 sdk/bin입니다.

## 조회 조건

거래소구분은 XML의 STKMKT 코드표를 사용합니다. 상하한구분과 장구분은 각각 1바이트 입력이며 초기값은 모두 1입니다. XML에 두 항목의 코드표 참조가 없습니다. 종목체크는 기본값 0 뒤를 공백으로 채우며, 시작가격·종료가격·거래량은 초기값 0과 자릿수를 유지합니다.

## 수신과 연속조회

A형, block=1, attr=1입니다. SDK가 통지하는 블록 이름을 사용하여 고정 응답 t1214OutBlock과 반복 응답 t1214OutBlock1을 구분합니다. 고정 응답의 idx와 cnt는 각각 연속 키와 종목수로 표시합니다. 반복 응답(occurs=1)의 실제 레코드 수는 블록 바이트 길이를 SDK 구조체 크기로 나누어 구합니다. ListView는 수신 건수와 별도로 최대 200건을 표시합니다.

처음 조회는 본문 idx를 공백 4바이트로 설정하고 4인자 RequestData를 호출합니다. 응답 헤더의 szPNFlag가 1이고 본문 idx가 유효하면 다음 조회에서 해당 idx와 빈 문자열 5번째 인자를 전달합니다. 조회 조건이 바뀌거나 연속 키가 반복되면 다음 조회가 비활성화됩니다.

## 오프라인 검증

Python 3으로 tests/run-offline.py를 실행하면 XML의 블록 선언과 SDK 헤더의 필드 배치를 확인하고, 실제 SDK 헤더를 사용해 Win32 Debug·Release를 빌드합니다. 오프라인 테스트는 로컬 모의 DLL로 실행합니다.
