# 주식체결/미체결 (d8317)

Visual Studio 2010 v100, Win32/x86, MultiByte, C++03, WinAPI GUI.
`OrdaAPI-d8317-StockOrders.sln`에서 Debug 또는 Release Win32를 빌드합니다.
작업 폴더를 저장소의 `sdk/bin`으로 설정하고 로그인 후 처음 조회와 다음 조회를 사용합니다.

## 현재 수신·파싱 방식

개발자가 작성한 `ReceiveData`의 `pOutBlock`, `pOutBlock1`, `for` 반복문과 `pOutBlock1++` 구조를 기준으로 완성했습니다.
건수·시작 위치·성공 반환값·완료 처리 연결은 사용자가 승인한 최소 보완 범위에서 변경했습니다.
수신 함수는 SDK가 조립하여 전달한 본문을 실제 SDK 구조체 포인터로 읽습니다.
별도의 본문 누적 버퍼나 파싱 계층을 사용하지 않습니다. 기존 비동기 통지의 데이터 복사와 재진입 큐는 유지합니다.

`d8317`의 본문은 `d8317OutBlock` 다음에 `d8317OutBlock1`이 반복 배치됩니다.
반복 건수는 `tqty[18]`이며 별도 5바이트 count는 존재하지 않습니다.
Header/XML의 tqty 설명은 총주문수량이지만 이 Sample은 사용자가 확인한 실제 서버 계약에 따라 반복 건수로 사용합니다.
BlockName은 출력 구조체를 구분하는 데 사용하지 않습니다.

고정 구조체 전체 길이를 먼저 검사한 뒤 `ParseCount`로 공백 패딩 가능한 tqty를 읽습니다.
빈 값·음수·비숫자·중간 공백·오버플로를 거부하고, 전체 본문은 INT_MAX 바이트 이내로 제한합니다.
본문 길이가 `sizeof(d8317OutBlock) + count * sizeof(d8317OutBlock1)`과 일치할 때만 반복 포인터를 순회합니다.
불완전·과다 본문과 중복 데이터 통지는 오류로 처리합니다. 완성되지 않은 본문 조각은 이 수신 함수의 정상 입력 계약에 포함되지 않습니다.

## 필드 추출과 결과 표시

`ReceiveFixed`는 고정 출력의 9개 필드를 처리합니다.
반복 건수, 총체결수량, 총미체결수량, 수수료, 총주문금액, 매도·매수 체결금액, 제세금과 연속주문번호를 표시합니다.
반복문의 `pOutBlock1->멤버`에서 26개 필드를 직접 추출하며 한글 항목명과 실제 SDK 필드명을 함께 표시합니다.
주문·원주문번호, 종목·거래소·매매구분, 주문·체결 수량과 가격, 미체결잔량, 상태, 시간, 호가·주문·신용구분 등을 확인할 수 있습니다.
전체 수신 건수는 별도로 표시하며 목록은 페이지당 최대 200행입니다.

`Field`는 고정 길이 문자열의 공백 패딩을 제거하고 화면에 표시할 문자열로 변환합니다.
주문번호·종목코드·업무 코드·날짜·시간의 선행 0을 보존합니다.
`NumberField`는 수량·금액을 64비트 정수로, 등락율을 실수로 변환합니다.
빈 숫자 필드는 빈 값으로 표시하고 잘못된 숫자는 형식오류와 원문을 표시합니다.
주문 상태 등 출력 업무 필드는 XML에서 코드표 참조가 지정되지 않은 문자열입니다. 의미가 확인되지 않은 코드를 임의로 다른 코드표에 연결하지 않고 원문으로 표시합니다.
입력 chegb·medosu·sortgb·exchange의 의미는 codes.xml의 FILLED·TRADE·SORT·EXCHANGE를 반영한 콤보박스를 따릅니다.
계좌 비밀번호는 마스킹되며 결과 목록에는 표시하지 않습니다.

## 연속조회와 완료

최초 요청은 4인자 `RequestData`, 다음 요청은 본문 `cts_ordno`와 5번째 인자의 SDK 연속키를 전달합니다.
커서 10바이트와 SDK 키 18바이트의 공백·선행 0을 보존합니다.
다음 조회는 정상 수신, 연속 플래그 1, 유효하고 이전과 다른 본문 커서, 유효한 SDK 키와 요청 해제 완료를 확인한 뒤 활성화합니다.
화면 표시는 RELEASE_DATA 통지에서 수행합니다. 오류가 발생한 요청의 결과는 지우고 다음 조회를 차단합니다.
요청·메시지 해제, 시스템 오류의 SDK 자동 해제 규칙, 타임아웃, 종료 중 통지 처리와 중복 요청 방지는 기존 흐름을 사용합니다.

## 오프라인 검증

`python tests/run-offline.py`를 실행합니다. 빌드와 가짜 DLL은 격리된 임시 폴더에서 실행합니다.
현재 개발자 수신 방식에 맞게 가짜 DLL은 완성된 고정+반복 본문을 전달합니다.
기존의 응용 계층 분할 누적 테스트는 완성 본문 검사와 불완전 본문 거부 검사로 변경했습니다.

Debug Win32 v100, Release Win32 v100 빌드 및 오프라인 전체 검사를 통과했습니다.
0·1·201건, 고정 길이 필드 추출, 18자리 금액 정밀도, 음수·소수 변환, 빈 숫자·잘못된 숫자·알 수 없는 업무 코드 표시를 검사했습니다.
잘못된 건수·서비스·요청 ID, NULL·음수 길이·버퍼 크기 불일치, 데이터 미달·과다·중복, 초기화·로그인·요청 실패, 완료 통지 대기, 타임아웃·종료·연속조회·메시지 및 요청 해제도 검사했습니다.
검증 기록은 `tests/offline-results.log`입니다.

## 향후 Header Type D Sample 참조

`main.cpp`의 `ReceiveData`에서 전체 경계를 검사한 뒤 실제 SDK 구조체 포인터를 사용하고, 반복문 안에서 각 멤버를 읽는 흐름을 기본 참조로 사용합니다.
문자열·숫자 표시는 Field·NumberField, 고정 출력 표시는 ReceiveFixed, 비동기 완료와 해제는 ProcessNotification을 참고합니다.

block=1이 아닌 전문은 BlockName으로 출력 구조체를 구분하지 않습니다.
고정·반복 구조체 배치와 반복 건수의 위치, 별도 count의 존재 여부는 서비스별 실제 계약을 확인합니다.
d8317의 tqty 건수와 별도 count 없음 규칙은 d8317 전용입니다.
다른 D형 전문에 이 규칙을 일괄 적용하지 않습니다.

실제 서버에서는 계좌 권한, 거래소별 응답, 커서와 SDK 연속키의 마지막 페이지 동작을 확인해야 합니다.
