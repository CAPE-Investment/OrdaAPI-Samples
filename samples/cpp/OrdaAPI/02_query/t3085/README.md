# t3085 — 옵션마스터조회(t3085)

옵션 마스터의 단축코드·표준코드·종목명을 반복 목록으로 표시합니다. [main.cpp](OrdaAPI-t3085-OptionsMaster/main.cpp)에서 입력·요청·응답·해제 흐름을 확인할 수 있습니다. 주문이나 실시간 자동갱신은 하지 않습니다.

## 개발 환경과 독립 빌드

- Windows / Visual Studio 2010 / Platform Toolset v100 / Debug 또는 Release / Win32(x86)
- MultiByte / C++03 / 순수 WinAPI. MFC와 SDK import library는 사용하지 않습니다.
- `OrdaAPI-t3085-OptionsMaster.sln`을 열어 빌드합니다. 결과는 이 Sample의 `bin/Debug`, `bin/Release`, 중간 파일은 `obj/<구성>`입니다.
- SDK 공개 Header는 `sdk/include/ordalib.h`, `errcode.h`, 전문은 `sdk/structs/cpp/t3085.h`를 참조합니다. 공개 Header 경로는 `ORDAAPI_INCLUDE_DIR`로 재정의할 수 있습니다.
- 기존 `common/OrdaSampleCommon.cpp`를 함께 컴파일합니다. 기존 공통 코드와 다른 Sample은 수정하지 않았습니다.
- C++ 소스는 UTF-8 BOM입니다. 화면은 Unicode WinAPI, SDK와 서버 원문은 MultiByte를 사용합니다.

## SDK 준비·실행·로그인

1. 공급된 SDK Runtime의 DLL과 `sys` 리소스를 `sdk/bin`에 준비합니다. `OrdaAPI.dll`, `OrdaAPISvr.dll`, `OrdaSDK.dll`, `OrdaSDKSvr.dll` 및 통신·인증 의존 DLL이 필요합니다.
2. 디버거 작업 폴더는 저장소의 `sdk/bin`으로 설정돼 있습니다. IDE 밖에서도 이 폴더를 작업 폴더로 지정합니다. Sample별 DLL 복사나 전역 PATH 변경은 필요하지 않습니다.
3. 개발/운영 서버와 접속정보, 로그인 ID·비밀번호·공동인증 비밀번호를 확인하고 **로그인**합니다. 비밀번호 입력은 마스킹됩니다.
4. 비동기 `WM_LOGIN` 완료 통지와 실제 로그인 상태를 확인한 뒤에만 조회할 수 있습니다. 즉시 반환만으로 로그인 성공을 판단하지 않습니다.
5. 오른쪽 조회 조건을 확인하고 **처음 조회**를 누릅니다. 결과는 가로·세로 스크롤 영역에 표시합니다.

로그인 실패 시 상태를 확인하고 종료 후 다시 실행하십시오. 기존 OrdaAPI 래퍼가 `LoadLibrary` / `GetProcAddress`로 DLL을 사용합니다.

## 입력 조건

`focode[8]`은 XML 명칭이 단축코드이며 기본값은 공백 8바이트입니다. 화면 기본값도 공백입니다. 빈 입력 또는 8바이트 이내 문자열을 공백 패딩하여 전송하고 길이 초과를 차단합니다. 공백이 전체 상품을 뜻하는지, 코드별 필터 범위와 유효 코드는 XML에 설명돼 있지 않으므로 서버 업무 규격 확인이 필요합니다.

입력은 실제 `t3085InBlock`을 속성 바이트까지 공백 초기화하고 Header의 실제 멤버에 설정합니다. 고정 길이 전송 필드에 종료 NUL을 추가하지 않습니다.

## 출력 블록과 주요 항목

`t3085OutBlock`이 XML의 `occurs="1"` 반복 블록입니다. 반복 레코드를 1건으로 고정하지 않습니다.

| 실제 멤버 | XML 명칭 | 데이터 바이트 |
| --- | --- | ---: |
| `shcode` | 단축코드 | 8 |
| `expcode` | 표준코드 | 12 |
| `hname` | 종목명 | 30 |

필드는 고정 길이 `char` 배열이며 `attr="1"`에 따라 속성 바이트도 존재합니다. 구조체를 지역 변수로 복사해 실제 멤버를 표시합니다. 표시용 복사본에서 끝 NUL·공백 패딩을 제거하고 선행 0·부호·소수점은 보존합니다. 내부 제어문자는 표시가 숨겨지지 않도록 `?`로 치환합니다. 숫자 변환·반올림·단위 변환을 하지 않습니다.

## 비동기 요청과 반복 응답

`WinMain` 초기화 → Common 연결/비동기 로그인 → `BuildInput` → `RequestMaster` → `CaptureNotification` / `ProcessNotification` → `ReceiveMaster` → 해제 순서입니다.

최초 조회는 다음 4인자 호출입니다.

```cpp
Common::Api()->RequestData(window, NAME_t3085, &input, sizeof(input));
```

즉시 반환 0~255는 요청 ID이며 최종 조회 성공이 아닙니다. 요청 ID·서비스·블록명·데이터 포인터·길이·Header 오류 플래그를 검사합니다. A형 반복 본문에는 별도 건수 접두부를 가정하지 않습니다. 데이터 길이가 실제 반복 구조체 크기의 배수인지 검사한 후 나눗셈으로 건수를 얻습니다. 0바이트 반복 블록은 NULL 데이터 포인터와 함께 와도 정상 0건으로 처리하며, 양수 길이의 NULL 포인터나 불완전한 마지막 레코드는 거부합니다.

같은 반복 블록이 여러 통지로 수신되면 이 요청의 레코드 수를 합산합니다. 전체 수신 건수는 계산하되 화면에는 페이지당 최대 200행만 표시합니다. 201건 이상을 200건으로 오인하지 않습니다. 새 조회/다음 페이지는 현재 페이지 표시를 교체합니다.

API 내부 재진입 통지는 빌린 버퍼가 유효할 때 복사하고 요청 ID 확보 후 순서대로 처리합니다. 요청 중에는 조건·조회 버튼을 잠그고 코드에서도 중복 요청을 차단합니다. 서버 오류·형식 오류·타임아웃에 자동 재시도하지 않습니다.

## 연속조회 범위

이 서비스에는 XML 출력 커서를 입력으로 되돌리는 명시적 매핑이 없습니다. 기존 t3084와 같이 최초 조회만 제공하며 임의의 다음 키를 만들지 않습니다. 서버가 연속 플래그를 보내면 상태 영역에 다음 조회를 제공하지 않는 이유를 표시합니다. 모든 종목을 한 번에 수신한다고 보장하지 않으며 실제 분할·연속 계약은 서버 규격 확인이 필요합니다.

## 메시지 해제와 종료

`MESSAGE_DATA` / `SYSTEM_ERROR_DATA`는 메시지 복사 후 `ReleaseMessageData()`로 해제합니다. 제품의 `nIsSystemError==1` 메시지 해제가 요청도 해제하는 동작을 반영해 중복 해제를 피합니다. 메시지 형식 오류를 원본 SDK 시스템 오류 값으로 덮어쓰지 않습니다.

일반 요청은 `RELEASE_DATA`·타임아웃·종료에서 `ReleaseRequestData()`로 정리합니다. 종료 시 게시 대기 메시지 정리 → 활성 요청 해제 → Logout → Disconnect → DLL 해제 → 창 파괴 순서이며 호출 중 종료는 호출 완료 후 처리합니다. 로그인 비밀번호를 결과에 출력하지 않으며 SDK 내부 로그 정책은 별도 확인 대상입니다.
