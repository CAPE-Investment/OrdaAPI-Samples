# 주식시간대별체결조회 (t1021)

Visual Studio 2010 v100, Win32, MultiByte, C++03, WinAPI GUI.
`OrdaAPI-t1021-StockExecutions.sln`을 열고 Debug 또는 Release Win32로 빌드합니다.
실행 작업 폴더는 저장소의 `sdk/bin`입니다. SDK DLL을 동적으로 로딩하며 기존 Common 로그인을 재사용합니다.
로그인 후 조건을 입력하고 처음 조회, 다음 조회 순으로 사용합니다.
목록은 페이지별 200행까지 표시하며 전체 수신 건수는 별도 표시합니다.

## 입력과 출력

실제 `t1021InBlock` 멤버에 값을 설정하며 XML 기본값을 적용합니다.
입력 필드는 shcode[6], cvolume[12], starttime[4], endtime[4], cts_time[10], exchange[1]입니다.
출력은 `t1021OutBlock` 및 반복 `t1021OutBlock1`입니다.
고정 출력의 합계와 반복 출력의 모든 필드를 표시합니다. 비밀번호는 마스킹하며 입력 전문을 출력하지 않습니다.

## 연속조회

최초는 `RequestData(window, NAME_t1021, &input, sizeof(input))`입니다.
다음은 위 인자에 5번째 인자 빈 문자열 "" (NULL이 아닌 포인터)를 추가합니다.
본문 커서는 cts_time이며 출력의 원본 고정 길이 바이트를 다음 입력에 복사합니다.
복합 커서는 모든 필드를 연결하여 비교합니다.
`szPNFlag == '1'`, 유효한 본문 커서, 직전과 다른 커서, 정상 응답 및 요청 해제 완료 후 다음 조회를 허용합니다.
A형 제품 헤더에는 SDK 연속키 매핑이 없으며 5번째 인자의 존재로 연속 플래그를 설정합니다.
빈·반복 커서 또는 연속 플래그 종료 시 다음 조회를 중지합니다. 조건을 편집하면 연속 상태를 초기화합니다.
진행 중 입력과 조회 버튼을 잠그며 자동 페이지 조회는 수행하지 않습니다.

## 수신 및 해제

A형은 블록명을 검증하여 고정 블록과 반복 블록을 각각 처리합니다. 블록 순서와 반복 블록 분할 통지를 허용합니다.
데이터는 SDK 소유 버퍼가 유효할 때 복사하고 재진입 통지를 큐로 처리합니다.
`RELEASE_DATA`까지 응답을 수집하며 오류·타임아웃·종료 시 요청을 해제합니다.
서버 메시지는 `ReleaseMessageData`로 해제하고 시스템 오류의 SDK 자동 요청 해제 규칙을 따릅니다.

## 오프라인 검사

`python tests/run-offline.py`로 Debug/Release 빌드와 격리 DLL 테스트를 실행합니다.
테스트 파일과 빌드 산출물은 기존 Git 제외 규칙을 적용합니다.
실제 SDK DLL 교체 및 실제 서버 연결은 수행하지 않습니다.

## 실제 서버 확인 항목

실계좌 권한, 업무별 마지막 페이지 플래그·커서·SDK 키, 거래소별 응답과 세션 오류를 확인해야 합니다.


## 생성 파일과 검증 결과

고객 배포 파일은 이 README, 루트 Solution, 프로젝트 폴더의 Project와 main.cpp 총 4개입니다.
오프라인 파일은 tests/fixture.h, tests/fake-api.cpp, tests/harness.cpp, tests/run-offline.py와 tests/offline-results.log입니다.
t1021/tests에는 개발용 generate.py 및 generate-tests.py도 포함됩니다.

2026-11-17 검증에서 XML/Header 필드 계약, Debug Win32 v100, Release Win32 v100 빌드 및 가짜 DLL 검사가 모두 통과했습니다.
초기화·로그인·요청 실패, 정상·0건·201건, 복수 수신 통지, 잘못된 요청 ID·서비스·블록·길이, NULL 데이터, 중복 요청, 타임아웃, 재진입·게시 메시지 대기 중 종료와 해제를 검사했습니다.
최초 4인자, 다음 5인자와 본문 커서, 빈·반복 커서, 마지막 플래그, 조건 변경을 검사했습니다.
D형은 각 서비스별 SDK 연속키의 공백 보존과 5자리 반복 건수 경계를 검사했습니다.
t1025와 d8810은 복합 커서의 마지막 필드만 바뀌어도 다음 페이지로 인식하는지 검사했습니다.

통신 패킷 분할 조립은 제품 ComGate.cpp의 수신 경로에서 확인했습니다. 가짜 DLL은 조립된 공개 API 통지를 모사하며 실제 전송 계층은 테스트 범위에 포함되지 않습니다.
A형에서 완전한 레코드 단위 응답이 일부만 도착한 뒤 정상 종료된 경우, t1021에는 기대 건수 필드가 없어 누락 여부를 자체 판정할 수 없습니다. 서버의 완료 통지를 기준으로 처리합니다.
