# 주식챠트(틱/n틱) (s4107)

Visual Studio 2010에서 [OrdaAPI-s4107-StockTickChart.sln](OrdaAPI-s4107-StockTickChart.sln)을 열고 Debug 또는 Release Win32로 빌드합니다. 실행 작업 디렉터리는 sdk/bin입니다. 기존 Common이 SDK DLL 로딩과 접속·로그인을 담당합니다.

Header Type A, block 1, attr 1입니다. 입력은 s4107InBlock입니다. SDK의 4인자 최초 조회 호출을 사용합니다.

| 출력 | occurs | 처리 |
|---|---|---|
| s4107OutBlock | 미지정 | 고정 구조체 1개 |
| s4107OutBlock1 | 1 | 블록 수신 길이 ÷ 구조체 크기 |

BlockName으로 각각 처리하며 블록 도착 순서와 무관합니다. 화면의 차트 목록은 200건까지 표시하고 수신 건수는 별도 집계합니다.

주식 단축코드는 6바이트입니다. ncnt는 n틱 단위, qrycnt는 요청 건수이며 각 필드는 숫자 문자 최대 4바이트입니다. nday는 조회 영업일수 1바이트이며 0은 미사용, 1~9는 영업일수 사용입니다. 시작일과 종료일은 각각 선택 항목입니다. 입력란은 처음에 비어 있으며 빈 입력이나 ASCII 공백만 입력한 값은 공백 8바이트로 전송합니다. 값이 있는 일자는 YYYYMMDD로 검사하고, 두 일자가 모두 입력된 경우 시작·종료 순서를 확인합니다. XML에서 미사용으로 명시된 시작·종료시간 stime/etime은 6바이트 공백입니다. 날짜와 nday를 함께 보낼 때의 우선순위 및 ncnt 허용 범위는 서버 확인이 필요합니다.

comp_yn의 XML 설명은 Y 압축, N 비압축이며 XML 기본값은 없습니다. 압축 최대 2000건, 비압축 최대 500건이 명시되어 있습니다. 제품 ComGate::RecvRequestData는 패킷의 WM_COMPRESS 플래그에 따라 LZO를 해제한 뒤 응답을 처리합니다. s4107에서 Y 요청 시 서버가 해당 전송 플래그를 사용하는지와 고객에 전달되는 서비스 본문 규격은 확인되지 않아 이 샘플은 N만 제공하고 요청 건수는 최대 500으로 검사합니다. fake DLL은 이미 구성된 비압축 SDK 수신 블록을 사용합니다.

고정 표에는 실제 시작·종료 시간, 처리 시간, 서버 rec_count 및 응답 연속키가 포함됩니다. 반복 표는 일자·시간·OHLC·거래량 및 수정주가 관련 필드를 표시합니다. 동일 시각 레코드도 수신 순서대로 표시합니다.

cts_date(8), cts_time(10)은 요청과 고정 출력에 모두 있습니다. 최초 요청은 두 필드를 공백으로 채웁니다. SDK의 Type A 헤더는 다섯 번째 인자의 포인터 유무로 연속 플래그를 설정하지만, s4107의 두 필드 재전달 조건과 응답 szPNFlag 관계를 확인할 근거가 없어 최초 조회만 제공합니다.

모든 수신값은 실제 SDK 구조체에서 고정 폭 문자열로 읽으며 단위를 변환하지 않습니다.

오프라인 테스트는 Python 3으로 tests/run-offline.py를 실행합니다. 버전 100 도구로 Debug·Release를 빌드하고 격리된 fake DLL과 WinAPI 메시지 테스트를 실행합니다. tests 디렉터리에는 기존 Git 제외 규칙이 적용됩니다.
