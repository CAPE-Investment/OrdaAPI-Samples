# 뉴스본문조회 (s2524)

Visual Studio 2010에서 [OrdaAPI-s2524-NewsContent.sln](OrdaAPI-s2524-NewsContent.sln)을 열어 Debug 또는 Release Win32로 빌드합니다. 실행 작업 디렉터리는 sdk/bin입니다. 기존 Common으로 DLL을 로딩하고 로그인한 뒤 뉴스번호를 입력해 조회합니다. 뉴스번호 sNewsno는 최대 24바이트이며 선행 0과 구분 문자를 문자열로 전송합니다.

## 수신과 표시

Header Type A, block 1, attr 미지정입니다. 요청은 SDK의 s2524InBlock을 사용합니다. 최초 조회를 제공합니다.

| BlockName | 표시 |
|---|---|
| s2524OutBlock | 관련 종목, 읽기 전용 멀티라인 Edit |
| s2524OutBlock1 | 뉴스 본문, 읽기 전용 멀티라인 Edit |
| s2524OutBlock2 | 뉴스 제목, 읽기 전용 한 줄 Edit |

수신 길이가 실제 버퍼 범위에 있는지 확인하고 BlockName별로 원본 바이트를 누적합니다. 같은 블록을 다시 받으면 기존 데이터 뒤에 수신 바이트를 그대로 붙입니다. Edit에는 끝에 NUL이 붙은 누적 문자열을 전달합니다. SDK 출력 구조체 크기로 길이나 건수를 판단하지 않습니다. 공백과 줄바꿈을 추가하거나 제거하지 않습니다. ANSI 시스템 코드페이지가 응답 인코딩과 일치하면 수신 경계에 걸친 한글도 양쪽 조각을 받은 뒤 표시됩니다.

세 Edit에서 선택과 복사가 가능하며, 관련 종목과 본문은 세로 스크롤을 지원합니다. 상태 영역에는 블록별 수신 바이트를 표시합니다. 신규 조회 시 세 영역과 누적 데이터를 비웁니다. 메모리 사용을 제한하기 위해 대기 중 복사본을 포함해 블록별 8 MiB 상한을 적용합니다. 수신 데이터에 NUL이 포함되면 원본 바이트는 보존되지만 Win32 Edit는 첫 NUL 앞까지만 표시합니다.

## 오프라인 검증

이 폴더에서 Python 3으로 tests/run-offline.py를 실행합니다. 실제 SDK 헤더를 사용한 v100 Debug·Release 빌드와 격리된 fake DLL 테스트를 수행합니다. 짧거나 구조체 크기의 배수가 아닌 수신 데이터, NUL 없는 데이터, 블록 순서 변경과 누적, CP949 한글 분할, LF·CRLF·공백 보존, 빈 응답, 긴 본문, 신규 조회 초기화 및 버퍼 경계를 검사합니다.
