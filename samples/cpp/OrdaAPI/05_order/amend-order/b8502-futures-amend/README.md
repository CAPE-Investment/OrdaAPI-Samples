# b8502 — 선물정정주문

[main.cpp](OrdaAPI-b8502-FuturesAmend/main.cpp)에서 초기화 → 로그인 → 입력 검증 → 사용자 확인 → 요청 → 비동기 응답 → 해제 흐름을 확인할 수 있습니다. 이 Sample은 선물 정정주문 전용 독립 Win32 프로그램입니다.

## 빌드와 실행

- Visual Studio 2010 / v100 / Win32(x86) / MultiByte / C++03 / 순수 WinAPI입니다.
- `OrdaAPI-b8502-FuturesAmend.sln`을 열고 Debug 또는 Release / Win32로 빌드합니다. 결과는 해당 Sample의 `bin/Debug`, `bin/Release`에 생성됩니다.
- SDK Header는 `sdk/include/ordalib.h`, `errcode.h`와 `sdk/structs/cpp/b8502.h`입니다. `ORDAAPI_INCLUDE_DIR` 재정의를 지원합니다.
- 기존 `common/OrdaSampleCommon.cpp`를 프로젝트에 함께 컴파일합니다. 소스는 UTF-8 BOM이며 화면은 Unicode WinAPI, 제품 API는 MultiByte를 사용합니다.
- 작업 폴더는 저장소의 `sdk/bin`입니다. `OrdaAPI.dll`, `OrdaAPISvr.dll`, `OrdaSDK.dll`, `OrdaSDKSvr.dll` 및 배포본의 통신·인증 DLL과 `sys` 리소스를 함께 사용합니다.

## 사용 순서

1. 서버·포트·사용자 ID·로그인 비밀번호·공동인증 비밀번호를 확인하고 **로그인**합니다.
2. 오른쪽 스크롤 입력 영역에서 계좌·입력비밀번호·선물종목번호와 정정 조건을 입력합니다.
3. **주문 전송** 후 확인창의 계좌·종목·수량과 해당 주문 조건을 확인하고 승인합니다.
4. 응답의 10자리 주문번호와 Header·서버 메시지를 확인합니다. 요청 ID는 접수된 API 요청을 구분하며 체결 완료를 의미하지 않습니다.
5. 이전 주문의 실제 결과를 확인한 뒤 **새 주문 준비** 확인을 거쳐 다음 주문을 전송합니다.
6. **로그아웃**은 세션을 정리하고 로그인 화면을 초기화합니다. 로그인 실패 후 **다시 로그인**을 사용할 수 있습니다. 서버·ID는 유지하고 비밀번호는 지웁니다.

## 가격·수량 형식

가격 `price[13]`은 정수부 10자리 + 소수점 + 소수부 2자리입니다.

| 입력 | 전송값 |
| --- | --- |
| `350.25` | `0000000350.25` |
| `350` | `0000000350.00` |
| `12.5` | `0000000012.50` |
| `0` | `0000000000.00` |

정수부는 1~10자리, 소수부는 최대 2자리입니다. 소수부가 없으면 `00`, 한 자리면 뒤에 `0`을 채웁니다. 빈 입력·음수·문자·복수 소수점·정수부 없는 `.25`·소수부 없는 `350.`·길이 초과를 차단합니다. 반올림·절단·부동소수점 변환을 하지 않습니다. 종료 NUL 없이 13바이트를 설정합니다. 별도 조건가격 필드는 없습니다.

수량 `qty[16]`은 1~16자리 숫자 문자열을 왼쪽 Zero Padding합니다. `10`은 `0000000000000010`으로 전송합니다. 빈 입력·음수·문자·소수점·길이 초과는 차단합니다. 가격이 있는 경우 가격과 수량, 취소에서는 수량의 앞뒤 ASCII 공백을 제거합니다. 숫자형으로 변환하지 않고 종료 NUL을 넣지 않으며 화면 입력값을 유지합니다.

## 원주문번호

XML의 `orgordno[10]`는 Header에서 `dummyorgordno[3]`과 `orgordno[7]`로 분리되어 있습니다. 화면에서는 하나의 원주문번호를 입력받습니다. 앞뒤 ASCII 공백을 제거하고 1~10자리 숫자인지 검증한 뒤 전체 10자리를 왼쪽 Zero Padding하고 각 멤버로 나눕니다.

| 입력 | 논리적 10자리 | dummyorgordno | orgordno |
| --- | --- | --- | --- |
| `12345` | `0000012345` | `000` | `0012345` |
| `1234567890` | `1234567890` | `123` | `4567890` |
| `00012345` | `0000012345` | `000` | `0012345` |

빈 입력·문자·음수·소수점·내부 공백·10자리 초과 입력을 차단합니다. 숫자형 변환·절단·종료 NUL 추가를 하지 않습니다. 확인창과 응답에서도 원주문번호를 논리적 10자리로 표시합니다.

## 요청·응답과 해제

`BuildInput`은 `b8502InBlock` 229바이트를 공백으로 초기화한 뒤 실제 멤버를 설정합니다. 고객용 소스에는 구조체 배치 검증 코드를 두지 않습니다.

```cpp
Common::Api()->RequestData(window, NAME_b8502, &input, sizeof(b8502InBlock));
```

`RequestOrder`는 입력 검증·사용자 확인·세션 확인·중복 차단 후 API를 호출합니다. 즉시 반환값 0~255는 요청 ID이고 최종 결과는 비동기 통지로 확인합니다.

`CaptureNotification`은 API 통지 버퍼를 유효한 동안 복사하고 재진입 통지를 순서대로 보관합니다. `Receiveb8502`는 서비스 코드·블록명·정확한 수신 길이 444바이트를 검사한 뒤 `b8502OutBlock` 229바이트와 `b8502OutBlock1` 215바이트를 읽습니다. 반복 응답을 가정하지 않습니다.

응답 주문번호는 `dummyordno[3]`과 `ordno[7]`을 연결하여 `orderNumber` 10자리로 표시합니다. Header 오류 플래그·메시지 코드·내용, `MESSAGE_DATA`, `SYSTEM_ERROR_DATA`를 구분하여 처리합니다. 응답의 계좌명은 해당 Header의 실제 멤버명을 사용합니다.

메시지는 복사·마스킹 후 `ReleaseMessageData()`로 해제합니다. 시스템 오류 시 이 호출이 요청도 해제하는 제품 동작에 맞춰 중복 해제를 방지합니다. 나머지 요청은 `RELEASE_DATA`·타임아웃·종료에서 `ReleaseRequestData()`로 정리합니다. 종료 순서는 요청 해제 → Logout → Disconnect → DLL 해제 → 창 파괴입니다.

## 주문 안전성과 확인이 필요한 업무 규칙

**실제 서버에서 전송을 승인하면 실제 주문이 발생할 수 있습니다.** 주문 확인창의 기본 선택은 취소입니다. 요청 중 전송·로그아웃·재로그인을 차단하고 자동 재주문·자동 재시도를 하지 않습니다. 다음 전송은 별도 새 주문 준비 확인을 거칩니다.

타임아웃·연결 단절·비정상 또는 누락 응답은 결과 미확정입니다. 실제 주문 내역을 확인한 후 다음 동작을 결정해야 합니다. 비밀번호 입력은 마스킹하며 응답 echo의 `passwd`와 서버 메시지에 포함된 요청 비밀번호를 Sample 로그에서 가립니다. SDK 내부 로그는 배포본 설정을 따릅니다.

0은 기존 b8500과 같이 숫자 형식 검증을 통과합니다. 서버의 0 허용 조건, 상품별 호가단위·수량 한도, 코드 참조가 없는 필드의 업무 규칙은 XML·Header만으로 확정되지 않았습니다. 정정·취소수량의 전량 지정 방법도 별도 확인이 필요합니다. 호가유형별 가격 필수 조건도 별도 확인이 필요합니다.


Sample 전용 가짜 DLL과 하네스가 서비스 코드·전체 요청 버퍼·XML 기본값·코드 선택·숫자 문자열 변환·확인 취소·마스킹·중복 차단·정상/오류 응답·타임아웃·로그아웃/재로그인·종료 해제를 검증합니다. 빌드·테스트 산출물은 임시 디렉터리에 생성합니다.

실제 서버 접속 및 실제 주문 테스트는 수행하지 않았습니다.
