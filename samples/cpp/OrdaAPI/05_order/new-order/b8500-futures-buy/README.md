# b8500 — 선물매수주문

[main.cpp](OrdaAPI-b8500-FuturesBuy/main.cpp)에서 입력 구성, 요청 API, 응답 처리와 종료 순서를 확인할 수 있습니다. 매매구분은 매수 `2`로 고정한 단일 계좌 선물매수 Sample입니다.

## 빌드와 실행

- Visual Studio 2010 / v100 / Win32(x86) / MultiByte / C++03 / 순수 WinAPI입니다.
- `OrdaAPI-b8500-FuturesBuy.sln`을 열고 Debug 또는 Release / Win32로 빌드합니다. 결과는 이 Sample의 `bin/Debug`, `bin/Release`에 생성됩니다.
- SDK Header는 `sdk/include/ordalib.h`, `errcode.h`, 전문 구조체는 `sdk/structs/cpp/b8500.h`를 참조합니다. `ORDAAPI_INCLUDE_DIR` 재정의를 지원합니다.
- 공통 로그인 Helper의 소스를 프로젝트에 함께 컴파일합니다. MFC나 별도 Helper DLL은 필요하지 않습니다.
- 디버거 작업 폴더는 저장소의 `sdk/bin`입니다. IDE 밖에서 실행할 때도 이 폴더를 작업 폴더로 지정합니다.
- 실행에는 `OrdaAPI.dll`, `OrdaAPISvr.dll`, `OrdaSDK.dll`, `OrdaSDKSvr.dll` 및 배포본의 통신·인증 의존 DLL이 필요합니다. `sdk/bin` 배포본과 `sys` 리소스를 함께 사용합니다.
- 소스는 UTF-8 BOM입니다. 화면은 Unicode WinAPI, 제품 API와 서버 원문은 MultiByte 경로를 사용합니다.

## 사용 순서와 주문 안전성

**실제 서버에서 주문 전송을 확인하면 실제 주문이 발생할 수 있습니다.**

1. 개발/운영 서버와 접속정보, 로그인 ID·비밀번호·공동인증 비밀번호를 확인하고 **로그인**합니다.
2. 오른쪽 스크롤 입력 영역에서 계좌·입력비밀번호·선물옵션종목번호·주문유형·호가유형·거래유형·가격·수량을 입력합니다.
3. **주문 전송** 후 확인창에서 계좌·종목·매수구분·호가유형·전송 가격·수량을 확인하고 승인합니다.
4. 비동기 응답의 실제 `dummyordno`, `ordno`와 서버 메시지를 확인합니다. 요청 ID는 API 요청 접수 결과이고, 응답 수신도 체결 완료를 의미하지 않습니다.
5. 다음 전송은 이전 주문 결과 확인 후 **새 주문 준비** 확인을 거칩니다. 요청 중 전송·로그아웃·재로그인을 막으며 자동 재주문하지 않습니다.
6. 로그인 실패 시 **다시 로그인**으로 세션을 초기화합니다. **로그아웃**은 로그인 중인 세션을 정리하고 로그인 화면을 초기화합니다. 서버·ID는 유지하고 비밀번호를 지웁니다.
7. 종료 시 활성 요청 해제 → Logout → Disconnect → DLL 해제 → 창 파괴 순서로 정리합니다.

타임아웃·세션 단절·잘못되거나 없는 응답은 최종 주문 결과 미확인으로 표시합니다. 새 주문 준비는 사용자가 실제 처리 결과를 확인한 후 명시적으로 수행합니다.

## 가격·수량 전문 형식

가격은 사용자 확인으로 확정한 **정수부 10자리 + 소수점 + 소수부 2자리, 총 13바이트**입니다. 부동소수점·정수형 변환 없이 문자열로 처리합니다.

| 화면 입력 | `price[13]` |
| --- | --- |
| `350.25` | `0000000350.25` |
| `350` | `0000000350.00` |
| `12.5` | `0000000012.50` |
| `0` | `0000000000.00` |
| `1964000` | `0001964000.00` |

가격·수량의 앞뒤 ASCII 공백을 제거합니다. 가격은 정수부 1~10자리, 소수부 최대 2자리이며 소수부가 없으면 `00`, 한 자리면 뒤에 `0`을 채웁니다. 빈 입력·음수·문자·복수 소수점·범위 초과·정수부 없는 `.25`·소수부 없는 `350.`은 차단합니다. 반올림·절단을 하지 않습니다.

수량은 1~16자리 숫자 문자열을 16바이트 오른쪽에 복사합니다. 예를 들어 `1` → `0000000000000001`, `10` → `0000000000000010`, `100` → `0000000000000100`입니다. 빈 입력·음수·문자·소수점·길이 초과는 차단합니다. 가격·수량 필드에는 종료 NUL을 넣지 않으며 화면 입력은 유지합니다. 다른 필드는 XML 기본값과 공백 패딩을 사용합니다.

가격 `0`은 지정된 포맷 예시에 따라 변환하며, 수량 `0`도 숫자 형식 검증을 통과합니다. 서버에서 0을 허용하는 조건, 호가유형별 가격 필수 조건, 상품별 호가단위·수량 한도는 XML·Header·기준 MFC Sample에서 확인되지 않았습니다. Sample은 해당 업무 조건에 대한 추가 판정을 하지 않으며, 실제 사용 전 서비스 규격 확인이 필요합니다. 별도 조건가격 필드는 없습니다.

## 요청·응답과 메모리 해제

- `WinMain` / `WindowProc`에서 공통 Helper로 초기화·연결·로그인합니다.
- `BuildInput`에서 `b8500InBlock` 224바이트를 공백으로 초기화하고 실제 멤버를 설정합니다.
- `FormatPrice`에서 확정한 13바이트 가격 문자열을 구성합니다.
- `RequestOrder`에서 사용자 확인·세션 확인·중복 차단 후 다음 API를 직접 호출하고 요청 ID를 보관합니다.

```cpp
Common::Api()->RequestData(window, NAME_b8500, &input, sizeof(b8500InBlock));
```

즉시 반환값 0~255는 요청 ID입니다. 최종 결과는 `WM_RECEIVE_DATA`에서 확인합니다. `CaptureNotification`은 콜백 버퍼를 유효한 동안 복사하고 재진입 통지를 보관하며, `ProcessNotification`은 요청 ID를 대조합니다.

`Receiveb8500`은 서비스·블록명·정확한 응답 길이 439바이트를 확인하고 `b8500OutBlock` 224바이트와 `b8500OutBlock1` 215바이트를 순서대로 읽습니다. Header B의 고정 블록이며 반복을 가정하지 않습니다. 실제 응답의 `dummyordno[3]`, `ordno[7]`를 각각 표시합니다. SDK Header의 `szRetFlag` 오류 표시와 서버 코드·메시지도 처리합니다.

`MESSAGE_DATA`·`SYSTEM_ERROR_DATA`는 복사·마스킹 후 `ReleaseMessageData()`로 해제합니다. 시스템 오류에서 이 호출이 요청도 해제하는 제품 동작에 맞춰 중복 해제를 방지합니다. 나머지 요청은 `RELEASE_DATA`·타임아웃·종료에서 `ReleaseRequestData()`로 정리합니다.

## 민감 정보와 오프라인 검증

로그인·공동인증·계좌 비밀번호 입력을 마스킹합니다. Sample 로그는 응답 echo의 `passwd`를 가리고, 요청에 사용한 비밀번호가 서버 메시지에 포함된 경우에도 가립니다. SDK 내부 로그 설정은 배포본의 기존 동작을 따릅니다.

Sample 범위의 `tests/`에서 가짜 `OrdaAPI.dll`을 사용합니다. Python 3와 VS2010 v100이 있는 환경에서 다음 명령을 실행합니다.

```text
python samples/cpp/OrdaAPI/05_order/new-order/b8500-futures-buy/tests/run-offline.py
```

스크립트는 임시 디렉터리에서 Debug/Release 빌드와 가짜 DLL·하네스 빌드를 수행합니다. 서비스 코드·구조체·XML 기본값·코드 선택·실제 요청 버퍼·가격/수량 경계값·입력 차단·확인 취소·마스킹·중복 방지·정상/오류 응답·타임아웃·로그아웃/재로그인·종료 해제를 검사합니다.

실제 서버 접속 및 실제 주문 테스트는 수행하지 않았습니다.
