# S3T 실시간 통합체결 Sample

기존 조회 Sample의 공통 로그인 Helper와 WinAPI 컨트롤을 사용합니다. 실행 직후 하나의 메인 윈도우에 로그인, 종목 요청, 현재 등록 종목, 수신 데이터 및 로그를 모두 표시합니다. 별도의 로그인 팝업이나 화면 전환은 없으며 요청 및 수신 코드는 main.cpp에 있습니다.

기존 조회 Sample의 가로 배치를 따라 왼쪽 로그인 영역은 공통 Helper의 위치와 크기를 그대로 유지하고, 오른쪽 x=580부터 요청·결과 영역을 배치했습니다. 입력 x=830, 요청 버튼 폭 110, 기본 글꼴과 ReadOnly 출력 스타일도 조회 Sample을 따릅니다. 로그인 전에는 요청 버튼이 비활성화됩니다.

## 빌드 및 실행

- Visual Studio 2010 / v100 / Win32 / C++03 / MultiByte / 순수 WinAPI. MFC 및 C++11 의존성 없음.
- OrdaAPI-s3t.sln을 열고 Debug 또는 Release / Win32로 빌드합니다.
- 프로젝트는 ../../common/OrdaSampleCommon.cpp를 직접 컴파일합니다.
- EXE는 bin/Debug 또는 bin/Release, 중간 파일은 obj에 생성됩니다.
- SDK 경로와 디버거 작업 폴더는 상대경로입니다. IDE 밖에서도 작업 폴더를 저장소 sdk/bin으로 지정하십시오.
- Runtime은 sdk/bin 전체를 사용하며 복사하지 않습니다. Release에는 x86 VC++ 2010 CRT가 필요합니다. C++ 소스는 UTF-8 BOM입니다.

## 사용 순서

1. 실행하면 로그인과 실시간 요청·결과 영역이 하나의 메인 화면에 함께 표시됩니다.
2. 서버, 포트, ID, 비밀번호 및 필요한 공동인증 비밀번호를 입력하고 로그인합니다.
3. 실패하면 오류를 확인하고 **다시 로그인**을 누릅니다. 세션·DLL·worker를 정리한 뒤 **같은 프로세스와 같은 창에서** 상태를 초기화합니다. 서버·ID는 유지하고 비밀번호는 다시 입력합니다.
4. 로그인 성공 후 같은 화면에서 요청 버튼이 활성화됩니다. 영문/숫자 6자리 종목코드를 입력하고 **요청**을 누릅니다.
5. 현재 등록 종목과 수신 데이터를 확인합니다.
6. 다른 종목으로 요청하면 기존 종목 해제 성공 후 새 종목을 등록합니다.
7. 종료하면 등록 종목 해제, 로그아웃, 연결 종료, DLL 및 스레드 정리를 수행합니다.

로그인·등록은 자동 수행하지 않습니다. Login 반환값만으로 성공 처리하지 않고 공통 Helper가 최종 통지와 세션 상태를 확인합니다. 수동 해제 버튼 없이 전환·종료 시 자동 해제합니다.

S3T 소스에 비밀번호 상수를 추가하지 않았습니다. 공통 Helper의 기존 개발용 기본값이 남지 않도록 컨트롤 생성 직후 및 서버 선택 직후 비밀번호를 비웁니다. 재시도에도 인증정보를 보관하거나 전달하지 않습니다. 비밀번호를 비우면 SDK의 클라우드 인증이 시작될 수 있습니다.

## 공통 Helper 재시도 기능

공통 Helper의 기존 ResetAfterCleanup(HWND)를 사용합니다. 이번 단일 화면 변경에서는 공통 Helper와 기존 조회 Sample을 수정하지 않았습니다.

순서: BeginClose → 현재 작업 완료 → 실시간 정리 → Cleanup → worker 종료 확인 → ResetAfterCleanup → Initialize.

ResetAfterCleanup은 API 인스턴스가 남아 있거나 Helper 호출 중이면 실패합니다. 이전 세션의 통지와 로그인 상태를 지우고 입력을 다시 활성화합니다. 서버·ID는 유지하고 비밀번호를 비웁니다. S3T는 프로세스·메인 윈도우·입출력 컨트롤을 재생성하거나 숨기지 않습니다. 현재 등록이 있으면 키를 먼저 해제하고, 재로그인 시 이전 수신 표시와 등록 상태를 비웁니다.

## 요청 및 수신 계약

서비스는 NAME_S3T(S3T), 입력 InBlock은 shcode[6]으로 총 6바이트이며 attr가 없습니다. API에는 별도의 7바이트 버퍼에 키를 복사해 NUL 종료하고 nUnitLen=6으로 전달합니다. 등록은 AdviseRealData, 해제는 같은 HWND·서비스·보관한 키·길이의 UnadviseRealData입니다.

| 상황 | 동작 |
| --- | --- |
| 최초 요청 | Advise 성공 후 현재 종목 저장 |
| 동일 종목 | 추가 호출 없음, 수신 유지 |
| 다른 종목 | Unadvise(old) 성공 → Advise(new) |
| 기존 해제 실패 | 신규 호출 차단, 이전 종목 상태 유지 |
| 신규 등록 실패 | 현재 종목·이전 표시를 비우고 UnadviseWindow로 잔여 상태 정리 |
| 요청 연타 | 진행 중 추가 요청 차단 |

API 성공 반환 1은 서버 등록 ACK나 실제 수신 성공을 보증하지 않습니다. 해제 실패 시 Sample의 기존 상태는 유지하지만 SDK 내부 상태나 수신 지속까지 보증하지 않으며 보상용 Advise를 자동 호출하지 않습니다.

수신은 API_BASE + WM_RECEIVE_REAL_DATA의 BC_ITEM_INFO입니다. 서비스, 본문 길이 223, 키 길이 6과 현재 등록 키를 확인한 후 지역 OutBlock에 복사하고 output.shcode도 비교합니다. 전환 중 데이터와 이전 키의 늦은 데이터를 무시합니다.

버퍼는 동기 통지 중에만 유효하므로 포인터를 보관·해제하지 않습니다. char 배열의 실제 길이로 변환하고 공백을 제거하며 NUL 종료를 가정하지 않습니다. 실제 필드 shcode, chetime, price, sign, change, drate, cgubun, cvolume, volume, value, cpower, offerho, bidho, status를 표시합니다. 유효 통지마다 UI 스레드에서 갱신합니다.

## 종료와 검증

등록 종목이 있을 때만 키 Unadvise를 호출하고 필요하면 UnadviseWindow를 추가합니다. 이후 공통 Cleanup이 Logout → Disconnect → DLL 해제를 수행합니다. worker 종료 확인 후 HWND를 파괴하며 해제 실패도 기록하고 후속 정리를 계속합니다.

VS2010 Win32 Debug·Release 빌드 및 저장소 밖 가짜 DLL로 다음을 검증합니다.

- 실행 직후 로그인·요청·수신 컨트롤이 같은 메인 윈도우에 존재하며 로그인 전 요청 비활성화
- 로그인 실패 후 동일 HWND/PID 및 동일 입출력 컨트롤에서 재시도 성공
- 등록 후 재로그인 시 기존 키 해제 → 세션 정리 → 새 로그인 → 새 종목 요청 성공
- 최초·동일·다른 종목 요청, 연타 방지, Unadvise → Advise 순서
- 기존 해제 실패 시 신규 호출 차단, 신규 등록 실패 시 상태 정리
- 이전 종목 데이터·잘못된 길이 거부 및 통지 버퍼 복사
- 전환 중 종료, 미등록 종료, 해제 실패 후 후속 정리

**실제 서버 테스트 미실시 — 사용자 직접 테스트 예정입니다.** 가짜 DLL은 Runtime에 복사하지 않았습니다. SDK·제품 소스·기존 조회 Sample 소스는 수정하지 않았습니다. 다른 서비스 개발과 Commit/Push는 수행하지 않았습니다.
